# Weave 기능 명세

macOS 메뉴바 포트폴리오 트래커. 메뉴바에 핀 자산 시세를 상시 표시하고,
클릭하면 360×720 팝오버에서 포트폴리오 전체를 관리한다.

- 스택: SwiftUI(MenuBarExtra) + Swift Charts, macOS 14+
- 디자인: `design/mockups-v5.html` 기준 (Slate/Light 테마, 링 게이지, 로고 마커 차트)
- 데이터 소스: Binance / Naver / Yahoo Finance 3개 고정, 사용자는 심볼 검색만

---

## 1. 메뉴바

- 표시 대상: 선택된 자산들을 N초 간격으로 로테이션(기본 10초). 특정 자산 핀 고정 가능.
- 형식: `BTC $60,000 ▲1.23%`, 등락 방향에 따라 ▲/▼.
  옵션: 풀(이름+가격+등락률) / 컴팩트(심볼+등락률) / 가격만.
- 표시할 자산이 없으면 포트폴리오 총액을 표시.
- 프라이버시 모드가 켜져 있으면 금액은 마스킹하고 등락률만 표시.
- 클릭 → 팝오버 열림. 팝오버 밖 클릭 시 닫힘.

## 2. 홈 (팝오버 메인)

### 2.0 헤더
- 좌측 새로고침 · 중앙 타이틀 · 우측 프라이버시 토글(eye) + 설정(gear). 아이콘은 8장 매핑 참조.
- **프라이버시 모드**: 켜면 앱 전체에서 금액(가격·평가금·손익액)을 마스킹,
  등락률(%)은 유지. 메뉴바에도 적용(1장).

### 2.1 링 게이지 3개
- **Day**: 오늘 등락 기여를 자산색 세그먼트로 분할. 포트폴리오가 이득이면
  이득 기여 종목만, 손실이면 손실 기여 종목만 포함(반대 부호 종목 제외).
  세그먼트 길이 = 해당 종목 기여액 비율.
- **Return**(중앙, 크게): 총 수익률. 분할 규칙은 Day와 동일.
- **Assets**: 평가금 비중 도넛(전 종목 자산색), 중앙에 종목 수.
- 세그먼트는 갭 없이 이어짐(butt cap). hover 시 굵어지며 기여액/비중 툴팁.
- 채움 스케일: Day 링 ±2% = 풀링, Return 링 ±25% = 풀링, 초과 시 꽉 찬 상태 유지.
- 자산 색: 고정 팔레트 8색을 추가 순서대로 자동 할당, 자산 관리에서 수동 변경.
  Assets 도넛은 비중 상위 4개 + 나머지 "기타"(회색) 묶음.

### 2.2 총액 영역
- 포트폴리오 총 평가금(기준통화 환산) + 등락률 솔리드 배지. 총액 hover 시
  원금과 부호가 포함된 미실현손익을 보여준다.

### 2.3 Value History 차트
- 필터: **통합**(포트폴리오 가치 라인 + 그라디언트 필) / **자산별**(종목별
  정규화 멀티라인, 시작점 0% 기준). 기간: 1M / 3M / 6M / 1Y.
- 표시 구간: max(선택 기간 시작, 첫 매수일)부터. 첫 매수 이전 구간은 없음.
- 통합 모드: 매수 이벤트 위치에 **자산 로고 원형 마커**(자산색 링).
  - hover → 툴팁(수량@가격 · 날짜 · 현재 대비 %) + 세로 가이드라인.
  - 클릭 → 해당 자산 상세로 이동.
  - 자산별 모드에서는 마커 숨김.
- 구현: Swift Charts `LineMark`+`AreaMark`, 마커는 `PointMark`+`annotation`,
  hover는 `chartOverlay`+`ChartProxy`.

### 2.4 Assets 리스트
- 행: 로고 · 이름 · 보유수량/매수횟수 · 현재가 · 등락 솔리드 배지.
- 정렬: 평가금 내림차순 고정.
- 행 클릭 → 자산 상세. 컨텍스트 메뉴: 핀 지정 / 숨김 / 삭제.

### 2.5 Footer
- 좌측: `Weave 0.1.0 · Next refresh in 4m` (버전 + 다음 시세 갱신 카운트다운).
  업데이트가 있으면 `Weave 0.1.0 → 0.2.0 사용 가능` 뱃지로 전환, 클릭 시 설치.
- 우측: ✎ 아이콘(자산 관리 화면 이동). 텍스트 버튼 없이 아이콘만.
- 설정 진입은 홈 헤더의 ⚙ 아이콘(9장).

## 3. 자산 관리 & 검색 (✎)

홈 footer의 ✎로 진입. 상단 검색바 + 보유 자산 관리 리스트로 구성.

### 3.1 검색 & 추가
- 검색창 하나. 2자 이상 입력 + 300ms 디바운스로 라이브서치.
- 3소스 병렬 질의 후 통합 리스트. 각 행에 마켓 뱃지: 크립토 / 국장 / 미장 / 일장 / 기타.
  - **Binance**: `exchangeInfo` 심볼 목록을 로컬 캐시 → 로컬 필터 (크립토, USDT 페어 기본)
  - **Naver**: `ac.stock.naver.com` 자동완성 (국장, 한글 검색)
  - **Yahoo**: `/v1/finance/search` (미장/일장/기타 글로벌, 폴백)
- 동일 종목이 여러 소스에서 나오면 하나만 표시: 국장=네이버, 크립토=Binance 우선.
  야후는 미장/일장 전담.
- 선택 시 provider · symbol · 통화 · 로고 자동 세팅으로 자산 생성. 중복 추가 방지.
- **Manual Asset**: 검색 불가 자산(부동산, 비상장 등)용. 이름/통화/평가액 수동 입력,
  시세 갱신 없음. 통합 차트에서 제외(또는 평단 고정선) 옵션.
- 로고: 크립토는 `cryptocurrency-icons` 아이콘셋, 국장·미장·일장은 네이버 증권 로고. 한 번 받아 `cache/logos/`에 저장한다. 로고가 없는 자산(ETF 등)은 이니셜 배지 폴백. 커스텀 로고·이니셜 배지까지 모든 로고는 원형으로 표시한다.

### 3.2 보유 자산 관리
- 자산 행: 로고 · 이름 · 메뉴바 표시 토글 · 색상 변경 · 숨김 · 삭제.
- 삭제는 거래 내역까지 통째 삭제, 확인 다이얼로그("거래 N건이 함께 삭제됩니다").
- 자산 수 soft limit 30개(API rate limit 보호).
- 빈 상태(자산 0개): 홈 대신 온보딩 화면 — 검색바 + "BTC, 삼성전자, AAPL 같은
  심볼을 검색해보세요" 안내.

## 4. 자산 상세

- 헤더: 뒤로 · 자산명 · 거래 추가(＋).
- 현재가 + 등락 배지 + 평단 대비 배지. 보유 평가금에 마우스를 올리면
  원금과 부호가 포함된 미실현손익 금액을 보여준다.
- 헤더 `LIVE` 토글: 켜면 해당 자산만 1초마다 샘플링해 1초 차트로 보여주고 상세 화면을 나가면 자동 종료.
- **김치 프리미엄 카드**(크립토, 기준통화 KRW일 때만): 업비트 원화가, 바이낸스가의 원화 환산(`$가격 × 원/달러`),
  김프 %, 30일 일별 김프 미니 라인과 최저~최고 범위. 시세 갱신 주기마다 다시 받고 `LIVE`와는 무관. 원/달러 환율은 5분 이내 값을 쓴다.
  업비트 원화 마켓에 없는 코인은 카드를 숨긴다.
- **차트** (Swift Charts):
  - 실제 캔들 종가 라인 + 그라디언트 필(자산색), 우측 y축 가격, 하단 x축 날짜.
  - 평단 점선(`RuleMark` + dash) + 라벨.
  - 매수(B, 초록)/매도(S, 빨강) 원형 마커 — hover 툴팁, 위치는 실제 체결가 좌표.
  - hover 크로스헤어 + 날짜·가격 툴팁.
  - 인터벌: 15m / 1H / 4H / 1D / 1W / 1M(월봉).
  - 탐색: 가로 드래그/스크롤 = 팬, 핀치 = 줌, 더블클릭 = 최신 구간 리셋.
    y축은 보이는 구간에 자동 피팅.
- **Trades 리스트**: 매수/매도 칩 · 수량@가격 · 날짜·메모 · 우측에
  매수는 "현재 대비 %", 매도는 "실현손익". 행 컨텍스트 메뉴로 수정/삭제.
- Trades 섹션 상단에 실현손익 누계 표시. 실현손익은 이 화면에만 노출
  (홈 링/총액은 미실현 기준 유지).

## 5. 거래 입력 (매수/매도)

- 필드: 종류(매수/매도) · 수량 · 단가 · 총액 · 날짜 · 메모.
- 수량/단가/총액 중 2개 입력하면 나머지 자동 계산.
- 과거 날짜 선택 시 그날 종가를 단가에 자동 프리필(캔들 캐시 활용, 수정 가능).
- 매도 검증: 보유 수량 초과 불가.
- 실현손익 = (매도단가 − 매도 시점 평단) × 수량. 평단은 이동평균법.

## 6. 시세 데이터 파이프라인

- **Quote(현재가)**: Binance ticker / Naver 시세 / Yahoo chart meta.
  주기 폴링(기본 300초, 설정 60~900초). 실패 시 마지막 값 유지 + stale 표시.
  상세 화면의 `LIVE` 토글은 선택 자산에 한해 1초 샘플링과 실시간 차트를 임시 적용한다.
- **Candle(히스토리)**: Binance klines / Naver fchart / Yahoo chart.
  인터벌 15m/1H/4H/1D/1W/1M. 로컬 캐시(`Application Support/Weave/cache/`) —
  일봉 이상은 하루 1회, 인트라데이는 5~30분 TTL 갱신.
  국장 인트라데이는 fchart 미지원이라 야후 `.KS`/`.KQ` 심볼로 브릿지.
  야후는 4H 미제공 → 1H를 클라이언트에서 합성. 홈 통합 차트는 일봉 고정.
- **환율**: Yahoo `KRW=X`, `JPY=X` 등. 1시간 캐시. 합산 계산은 기준통화로 환산.
- 자산의 통화는 provider가 아니라 **상장 시장**이 정함(야후에서도 005930.KS는
  KRW). 자산 행 표시는 기본적으로 소스 통화 그대로, 환산은 합산에만 적용(9장).
- provider는 프로토콜로 추상화(Naver/Yahoo는 비공식 API — 스펙 변경 시 어댑터만 교체).

## 7. 포트폴리오 계산

- 종목: 평단(이동평균) · 보유수량 · 평가금 = 수량×현재가 · 미실현손익 · 수익률 ·
  일간 변동 · 비중.
- 일간 변동 기준은 소스 제공값 그대로: 크립토 = 24h 롤링(Binance), 주식 = 전일
  종가 대비. 억지로 통일하지 않음.
- 포트폴리오: 종목 합산(환산 후) · 총 수익률 · 일간 변동 · 링 기여도
  (포트폴리오 손익과 같은 부호인 종목의 손익 비율) · 실현손익 누계.
- **가치 시계열**(통합 차트용): 일별 Σ(그날 보유수량 × 그날 종가 × 그날 환율).
  보유수량은 거래 날짜 기준 스텝 함수. 캔들 캐시로 로컬 계산.

## 8. 테마 & 아이콘

- **Slate**: 푸른기 도는 차콜(#2B2D35 베이스) + 비비드 시스템 컬러.
- **Light**: 밝은 회색(#F4F4F6) + 라이트 시스템 컬러.
- 기본은 **시스템 외관 따라가기**(다크→Slate, 라이트→Light), 설정에서 수동 고정 가능.
- 색은 전부 시맨틱 토큰으로 관리(목업 변수 그대로 이식).

### 아이콘 정책
- 앱 내 모든 아이콘은 **SF Symbols** 사용. 이모지·컬러 글리프 금지.
- 모노크롬, 색은 시맨틱 토큰(보통 `--text2`, 활성 시 `--link`/`--green`)을 따름.
- HTML 목업의 글리프(↻, ⚙, ✎ 등)는 근사치일 뿐, 구현 기준은 아래 매핑.

| 위치 | 기능 | SF Symbol |
|------|------|-----------|
| 홈 헤더 좌 | 수동 새로고침 | `arrow.clockwise` |
| 홈 헤더 우 | 프라이버시 토글 | `eye` / `eye.slash` (켜짐 상태) |
| 홈 헤더 우 | 설정 진입 | `gearshape` |
| 홈 footer 우 | 자산 관리 진입 | `square.and.pencil` |
| 공통 헤더 좌 | 뒤로 가기 | `chevron.left` |
| 상세 헤더 우 | 거래 추가 | `plus` |
| 자산 관리 행 | 메뉴바 표시 | `menubar.rectangle` |
| 자산 관리 행 | 숨김 / 삭제 | `eye.slash` / `trash` |
| 설정 | 단축키 등록 | `keyboard` |
| 설정 | 앱 종료 | `power` |
| 검색 | 검색 필드 | `magnifyingglass` |

## 9. 설정 화면 & 다국어

- 진입: 홈 헤더의 ⚙ 아이콘 → 팝오버 내 설정 화면(‹ 로 복귀, 세로 스크롤).
- UI: 섹션 라벨 + **그룹 카드**(rounded), 행 우측에 컨트롤 — 토글 / select
  드롭다운 / 버튼. (OpenUsage 설정 화면 스타일)
- **General**
  - 로그인 시 자동 시작(토글, `SMAppService`)
  - 글로벌 단축키(record 버튼) — 팝오버 열기
  - 메뉴바 로테이션 간격(select: 5초/10초/30초/끔)
- **Appearance**
  - 테마(select: 시스템/Slate/Light, 기본 시스템)
  - 언어(select: 시스템/한국어/English, 기본 시스템)
- **Data**
  - 시세 갱신 주기(select: 1/5/10/15분)
  - 기준 통화(select: KRW/USD/JPY; 신규 설치 기본값은 한국어 시스템 KRW, 일본어 시스템 JPY, 그 외 USD)
    — 총액·통합 차트 등 **합산 계산에만** 사용
  - 자산 표시 통화(select: **소스 통화 그대로**(기본) / 기준 통화로 환산)
    — 소스 통화면 BTC는 $, 삼성전자는 ₩로 각자 표시
  - 데이터 백업/복원(버튼) · 캔들 캐시 비우기 · 백업 export 성공 후 전체 데이터 완전 삭제
- **Updates**
  - 자동 업데이트 확인(토글) · 지금 확인(버튼) · 릴리즈 노트 링크
- 맨 아래: **Weave 종료** 버튼(+ ⌘Q) — 메뉴바 앱이라 Dock 종료 동선이 없음.
- Footer: 버전 + 다음 갱신 카운트다운.

## 11. 데이터 저장

- `Application Support/Weave/portfolio.json` — 자산 · 거래(매수/매도) · 설정.
- 스키마에 `version` 필드, 로드 시 마이그레이션 체인.
- 시세/캔들/환율 캐시는 별도 파일(포트폴리오 데이터와 분리, 삭제해도 무해).
- `sources`는 연결한 계좌·지갑 목록(종류 · 표시 이름 · 가린 계좌/주소 요약 · 마지막 동기화).
  키와 전체 주소는 문서에 저장하지 않는다. 가져온 거래는 `sourceID`와 소스의 체결 ID(`externalID`)를 가지고,
  직접 입력한 거래엔 둘 다 없다.
- 연결한 소스나 가져온 거래가 생길 때만 `version` 3으로 저장한다. 그 전엔 v0.1.x 앱도 열 수 있게 2로 둔다.
  v0.1.x 앱은 version 3 파일을 연결 데이터를 지운 채 덮어쓰지 않고 거부한다.

### 계좌·지갑 연결

설정 › 연결한 계좌. 지금은 토스증권과 코인 지갑을 연결할 수 있고, 한국투자증권은 이후에 붙인다. 업비트는 API 키에
고정 IP 등록이 필요해서 뺐다.

- **토스증권**: WTS › 설정 › Open API에서 받은 client ID·secret을 넣는다. Weave가 키를 확인하고 종합매매 계좌를
  골라 키와 `accountSeq`를 macOS 키체인(이 Mac 전용)에 저장한다. 문서엔 가린 계좌번호(`••••8901`)만 남는다.
- **허용 IP**: 토스는 WTS에 등록한 IP에서만 응답한다. 다른 네트워크에선 동기화가 실패하고 어디에 IP를 등록하는지
  알려 주며, 마지막으로 동기화한 데이터는 그대로 둔다. **지금 네트워크 IP 확인** 버튼은 누를 때만
  `api.ipify.org`를 부른다.
- **읽는 것**: 보유(수량 · 평단)와 주문. 첫 동기화는 계좌 개설 이후 끝난 주문 전체를, 그 뒤엔 마지막 동기화 7일
  전부터 읽는다. 주문 1건이 총 체결 수량·평균 체결가로 1행이라 주문 하나가 가져온 거래 하나가 된다
  (`externalID` = 주문 ID). 일부 체결 후 취소·정정된 주문은 체결분만 남기고, `CANCEL_REJECTED`·
  `REPLACE_REJECTED` 레코드는 뺀다. 보유와 진행 중 주문은 주문 내역 앞뒤로 두 번 받아서, 그사이 움직였거나
  체결 중인 주문이 있는 종목은 이번엔 보유 대조를 미룬다. 주문 API는 부르지 않는다.
- **접근 토큰**: 토스는 클라이언트당 유효 토큰이 하나라서 만료 1분 전까지 재사용하고, 401이면 한 번만 다시 받는다.
- **첫 동기화**는 검토 화면(새 거래 · 중복 의심 · 확인 필요 · 새 자산 · 기초 잔고)으로 간다. 그 뒤로는 시세 갱신과
  함께, 최소 5분 간격으로 검토 없이 반영한다.
- **새 자산**: 국내 주식은 Naver, 미국 주식은 Yahoo로 만든다(`BRK.B` → `BRK-B`). 다 팔았고 Weave에 자산도 없는
  종목은 가져오지 않는다. 자산 한도(30개)로 못 만든 종목의 거래는 기다리고 `lastSyncedAt`도 그대로 둬서,
  자리가 나면 들어온다.
- **마지막 동기화**는 검토를 나중에 적용해도 스냅샷을 받은 시각으로 둔다.
- **연결 해제**: 키, 가져온 거래, 거래가 전부 그 계좌에서 온 자산을 지운다.

#### 지갑

- **비트코인**: 지갑 하나에 주소 여러 개. `mempool.space`에서 확정 잔고를 읽는다. xpub 자동 탐색은 아직 없다.
- **EVM**: 주소 하나로 Ethereum, Arbitrum, Base, Optimism, Polygon 중 고른 체인을 본다. 체인마다 공개 RPC를
  Multicall3로 한 번 불러 가스 코인과 정해진 토큰 목록의 잔고를 읽는다. 목록(`EVMTokenList.swift`)은
  `scripts/update-evm-tokens.py`가 Uniswap 기본 목록 ∩ 바이낸스 USDT 마켓으로 만든다(목록에 남은 KNC v1 같은 옛
  컨트랙트는 바이낸스에서 거래되는 새 컨트랙트로 바꾼다). 모르는 컨트랙트는 읽지
  않아서 심볼을 흉내 낸 스팸 토큰이 들어오지 않는다. WETH는 ETH로 센다. 잔고 조회가 하나라도 실패하면 0으로
  보지 않고 동기화를 멈춘다.
- **이자·스테이킹 토큰**(`EVMYieldTokens.swift`, 손으로 관리, 주소마다 체인에서 확인): Aave v3 aToken, static
  aToken(waEth…), Umbrella 스테이킹 토큰(stkwaEth….v1)은 그 토큰 자체가 자산이 된다(예: "Aave Umbrella USDC ·
  stkwaEthUSDC.v1"). 시세 출처는 `onchain`이다. 가격은 금고의 1개당 `convertToAssets` 교환비(Umbrella는 stk →
  waEth → 원금, aToken은 1:1, 60초 캐시) × 원금 코인의 바이낸스 시세다. 차트는 원금 캔들 × 지금 교환비, 로고는
  원금 코인 것이다. 금고 토큰은 이자가 가격 상승으로 보인다. USDT·GHO가 원금인 토큰은 바이낸스 시세가 없어
  "가져오지 않은 잔고"로만 보인다. 지갑의 $5 미만 변화는 쌓였다가 한 번에 기록해서 이자가 동기화마다 거래를 남기지 않는다.
- **연결 상세**: 연결을 누르면 종류, 주소, 체인, 마지막 동기화, 가져온 보유, 가져오지 않은 잔고($10 미만·바이낸스
  시세 없음)를 큰 순서로 보여 준다.
- **코인**: 바이낸스 USDT 마켓이 있는 코인만. 새 코인은 바이낸스 자산(`BTCUSDT`)으로 만든다. $10 미만 잔고로는 새
  코인을 들이지 않지만 지갑이 이미 가진 코인은 계속 대조해서 $10 언저리에서 들락거리지 않는다. 잔고는 있는데 시세가
  없는 코인(상장 폐지·거래 중단)은 0으로 보지 않고 그 동기화에서 건너뛴다.
- **거래 기록이 없다**: 지갑엔 잔고뿐이라 변화는 직접 입력분과의 이동으로 기록한다.
  - 지갑이 늘면 → 같은 만큼 직접 입력분에서 평단 그대로 옮겨 온다. 직접 입력분으로 못 채운 만큼은 시세로
    시작한다(첫 연결은 기초 잔고, 그 뒤엔 잔고 맞춤).
  - 지갑이 줄면 → 차이를 지갑 평단 그대로 직접 입력분으로 돌려놓는다. 거래소로 옮겨 팔았으면 거기서 매도를
    직접 입력하면 된다.
  - 이동은 양쪽 다 잠긴다. 거래 목록엔 지갑 쪽 **이동** 한 줄만 보이고, 매수·매도 횟수, 차트 표시, 자산 전체 평단과
    실현손익에서 빠진다(보관 위치별 원장만 이동을 쓴다).
  - 지갑은 함께 동기화한다. 줄어든 지갑을 먼저, 늘어난 지갑을 나중에 반영해서 연결한 지갑끼리 옮긴 코인이 어느 지갑을
    동기화하든 두 번 잡히지 않는다.
  - 지갑으로 옮겨 간 직접 입력 매수는 지우거나 옮겨 간 만큼보다 작게 고칠 수 없다.
  - 연결을 해제하면 이동 기록이 지워져 직접 입력분이 돌아온다. 돌아온 코인을 그 뒤에 직접 팔았다면 그 자산의 직접 입력
    쪽 이동은 메모를 단 일반 거래로 남겨서 직접 입력분이 마이너스가 되지 않게 한다.

- **이미 가져온 체결**: `externalID`가 문서에 있으면 건너뛰고, 같은 동기화 안의 반복도 건너뛴다.
- **직접 입력한 같은 거래**: 같은 자산·방향·수량, 같은 날, 단가 1% 이내면 중복 의심으로 올린다.
  기본은 가져온 기록으로 합치고 직접 입력 쪽을 지운다.
- **기초 잔고**: 받아온 체결 이력보다 보유가 많으면 이력 시작 직전에 기초 잔고 매수를 넣는다. 단가는 이력을
  재생했을 때 소스 평단이 나오도록 역산한다. 계좌·자산당 하나.
- **잔고 맞춤**: 계좌가 원본이라 이력으로 설명 못 하는 차이는 동기화 시각의 잠긴 거래로 메운다. 이력보다 적게
  가지면(출고·시간외 매도) 평단으로 매도해서 실현손익이 생기지 않게 한다(병합은 평단이 예전 그대로 남는다).
  이미 가져온 거래가 있는 종목을 더 가지면(입고·분할) 평단이 계좌 평단과 같아지는 단가로 매수하고, 분할이면
  그 단가는 0이다. 기초 잔고는 첫 가져오기에만 쓴다.
- **확인 필요**: 이력이 중간에 마이너스가 될 때, 소스가 평단을 안 줄 때, 같은 자산에 직접 입력한 거래가 있어
  기초 잔고와 겹칠 수 있을 때(그 거래를 지우면 다음 동기화 때 계좌에 맞춘다). 자동으로 채우지 않는다.
- **소액**: 기준(₩10,000 예정) 미만 보유는 건너뛴다. 이미 자산으로 있는 종목은 예외.
- **잠금**: 가져온 거래는 앱에서 고치거나 지울 수 없다(원본이 소스). 직접 입력 매도는 직접 입력한 수량까지만
  팔 수 있어서 연결한 계좌의 보유를 줄이지 못한다.
- **자산 삭제**: 가져온 거래도 같이 지운다. 연결한 계좌에 아직 있으면 다음 동기화 때 다시 들어온다.
- **보관 위치**: 가져온 거래가 있는 자산은 상세 화면에 계좌·지갑별, 직접 입력별 보유를 보여 준다.
